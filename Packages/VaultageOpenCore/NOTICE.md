## Planned first-party boundary

The authorized architecture uses Apache-2.0 for original independent Core/generic MCP source and proprietary treatment for maintained provider adapters and catalog, hosted account/billing service, identity and billing integrations, and provider registrations. The scoped first-party mapping is [legal/LICENSE-SCOPE.md](legal/LICENSE-SCOPE.md), with the Apache-2.0 text in [legal/LICENSE-APACHE-2.0.txt](legal/LICENSE-APACHE-2.0.txt). This mapping covers original `Sources/VaultageCore/**`, `Sources/VaultageMCP/**` and `Sources/VaultageBrokerContract/BrokerProtocol.swift` and `BrokerWire.swift` only; it is not a blanket license for the repository or the mixed app bundle.

The Swift package keeps a clean generic MCP target edge: `VaultageCore` has no target dependencies and `VaultageMCP` declares only `VaultageCore` plus the external `MCP` module. `VaultageProviders` contains the maintained adapters and the service catalog and remains a separate proprietary target used by `VaultageApp`, `VaultageBrokerService` and `VaultageSelfTests`. The XPC custody contract was split on 2026-09-11 so the boundary is physical: `BrokerProtocol.swift` and `BrokerWire.swift` are the generic, value-free halves and are exported, while `BrokerContract.swift` keeps Vaultage's distribution identity (Developer ID team, bundle identifiers, code-signing requirements and the packaging script's Info.plist key) and is not. The allowlisted standalone package under [distribution/open-core/](distribution/open-core/) is generated by [scripts/export-open-core.mjs](scripts/export-open-core.mjs); the 2026-09-11 snapshot contains 38 hashed files and its standalone `swift build` passed. See [legal/OPEN-CORE-RELEASE-CHECKLIST.md](legal/OPEN-CORE-RELEASE-CHECKLIST.md).
